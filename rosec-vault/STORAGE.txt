Native vault storage

Vault format versions describe the serialized payload, not the rosec release.
Reads never upgrade files. The writer selects the oldest lossless representation.
Unknown versions are rejected, not guessed. V2 stores the original payload. V3 additionally stores per-secret content types
inside the encrypted payload. Only non-default content types require v3.
Removing/resetting the last such type lets the next write use v2 again.
V3 also includes a format-specific prefix in its MAC input: changing the header
to v2 fails authentication, including with an older v2 reader. Key wrapping and
KDF parameters are unchanged. V2 output retains the original MAC convention.

An unlocked vault holds an OS file lease. A second writer or recovery operation
must wait until it is locked/dropped (operations currently return an in-use error).
The adjacent .lock file must stay in place. An on-disk revision check additionally
rejects saves after an external replacement. Older rosec binaries do not obey this
lease; never run old and new writers concurrently against the same vault.

Writes use unique restrictive temporary files, file sync, rename and directory
sync. Each format transition retains the previous encrypted file under a unique
<path>.recovery-<uuid> name. Normal same-format writes do not create snapshots.
A snapshot contains the passwords/wrapping entries that existed at that time.
Snapshots are not automatically deleted; they may retain deleted secrets or old
unlock passwords, so remove recovery points when no longer needed.

Recovery command (stop rosecd first):
  rosec vault snapshot restore SNAPSHOT --path VAULT --yes

The command asks for the snapshot password, authenticates/decrypts its contents,
preserves the active encrypted file as another recovery point, and restores the
snapshot. Changes made since the snapshot are absent from the restored vault.
The metadata sidecar is rebuilt, not restored from an old sidecar snapshot.
The library also exposes LocalVault::restore_snapshot for controlled callers.
If directory sync fails after rename, the new file may already be active; an
error is returned rather than claiming crash durability. Reopen before retrying.

MIME input semantics
CreateItem replacement replaces both bytes and types; absent types mean text/plain.
ItemUpdate preserves unspecified types, including for byte-only callers. Explicit
text/plain removes a non-default type. Types for absent secret keys are rejected
before modifying the item. Types and bytes are read under the same native lock.
No content types are exposed in public item attributes or the metadata sidecar.
Existing external providers default to text/plain; WASM guest exports and JSON
remain unchanged. Standard SetSecret and property setters remain unsupported.

Verification
cargo test --workspace (run within dbus-run-session)
cargo clippy --workspace --all-targets -- -D warnings
bash tests/libsecret_roundtrip.sh (requires libsecret development headers, cc and pkg-config)
Set CARGO_TARGET_DIR to a disk-backed build directory when using /tmp worktrees.
The optional libsecret test uses only a private bus and temporary native vault.
It covers text workflows, binary MIME parameters and replacement with empty text.

The former `provider restore-snapshot --path VAULT --snapshot SNAPSHOT --yes`
spelling remains a deprecated alias. Both invoke the same native-file handler.
